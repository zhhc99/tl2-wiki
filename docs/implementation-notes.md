# 本轮实现取舍

本文只记录需求未明确规定、实现时需要自行确定的内容。

## 装备与孔数

- 玩家装备列表只保留 `rare`、`unique`、`legendary`，白色 `normal` 记录仍存在于原库，但不进入生成 JSON。
- 装备需求等级和掉落上下限以 schema version 4 的 `items.required_level`、`drop_min_level`、`drop_max_level` 为第一优先级；旧规范化补充只作为缺值回退。
- 装备效果改用 schema version 5 的 `item_display_effects`，只读取 `is_player_visible=1` 的最终有效词缀。该投影已处理继承覆盖、物品等级曲线、触发技能名与三语占位符；旧英文补充不再参与装备效果显示。
- 数据核对后把“蓝色装备最多 4 孔”收窄为“蓝色稀有武器最多 4 孔，盾牌除外”。附魔绿色武器最多 3 孔；The Asphyx 两件特殊装备、Netherrealm 武器和盾牌单列说明。
- 机制页将孔数规则保留在一个段落内，并在一般初始孔数、打孔上限、特殊装备三个加粗小节前断行；角色与装备专名优先采用数据库官方译名。
- `speed` 只对武器显示，并按游戏面板命名为“攻击速度”；数值仍以秒显示。孔数从装备列表和详情完全移除。

## 装备、套装与技能效果

- 套装效果改用新版数据库的 `set_display_effects` 最终显示层，并按内部 `set_id/internal_name` 识别套装；同名但内部不同的套装不会再被配装器错误合并。
- 持续伤害遵循游戏面板的舍入顺序：先把每秒伤害向上取整，再乘持续秒数。该规则同时用于装备和套装效果，修正了 Dispatch 的 `5880` 与 Unearthly 的 `2320`。
- 职业技能目前没有与装备等价的最终显示表，因此由导入器把技能等级节点、词缀、`effect_display_templates` 与曲线表结构化关联。没有玩家文案的 `ADD/REMOVE TRIGGERABLE`、`ADD/REMOVE STAT` 等运行时节点不会进入页面。
- 固定技能伤害、固定减甲和图表型法力消耗等随角色等级变化的数值不再显示为“原值 × 等级”。页面导出实际使用的曲线点，并提供角色等级输入；切换技能等级时先采用 `REQUIREMENT_GRAPH` 给出的最低可学等级，玩家仍可上调至 100 级查看实际数值。
- 技能模板中的伤害类型、持续时间、范围值、触发技能名与多值占位符由结构化字段填入；Rapid Fire 额外显示每秒法力、武器伤害、击退和减甲，Glaive Throw 额外显示实际毒素伤害范围、打断、减速与怒气生成。

## 技能书

- 194 条技能书改为直接按 GUID 读取 `skill_books`，不再通过共享技能图标猜测名称和说明。
- 简中、繁中名称与说明现已全部覆盖；技能书分组和类型继续沿用已提交的规范化分类，等级、需求和图标以主库为准。

## 配装面板

- 使用 12 个角色栏位，并按主手、副手、头盔、肩甲、胸甲、手套、腰带、腿甲、靴子、项链、戒指 1、戒指 2 的顺序排列。
- 双手武器会占用副手；副手只接受单手武器或盾牌。宠物装备与镶嵌物不进入角色配装器。
- 四职业使用游戏初始属性：狂战士 15/15/5/5、塞外客 10/15/10/5、烬石法师 5/10/15/10、工程师 15/5/5/15。每升一级提供 5 点，100 级上限为 495 点。
- 只自动汇总能够无歧义解析的固定被动属性词缀；随机范围、按等级缩放和条件触发词缀继续显示在效果汇总中，不擅自折算为面板属性。
- 装备需求按游戏的“角色等级满足，或全部属性需求满足”处理；职业限定始终需要满足。套装按已穿件数激活对应固定属性层级。
- 属性检视采用现有机制页公式，并叠加装备和已激活套装的固定被动词缀。专注伤害加成只显示专注本身提供的单一百分比，具体元素装备词缀留在效果汇总；格挡计入盾牌基础值，全伤害增加只统计 `PERCENT DAMAGE BONUS + ALL`，全伤害减免统计 `PERCENT DAMAGE TAKEN + ALL`。
- 狂战士与工程师的职业固有全伤害减免按 25% 计入；塞外客与烬石法师为 0%。这项职业基础值目前由前端规则维护，不来自装备数据库。
- 配置保存于浏览器 `localStorage`，不引入账户或远程存储。首次挂载先完成缓存恢复再写回，避免页面导航或刷新时用默认值覆盖旧配置；恢复旧配置时也会清理双手武器旁遗留的副手物品。
- 装备选择器按当前职业过滤，切换职业会卸下不兼容装备。等级和全部属性需求均未满足时，栏位使用错误状态提示，但仍允许保留该模拟配置。
- 从选择器点选装备后先打开预览，确认后才放入栏位并关闭预览。装备栏的需求警告放入名称信息流，不再与等级文字绝对定位叠放。
- 装备详情用“物品等级 + 类型”替代独立的等级数值格。需求按“需求等级，或全部属性条件；另需满足职业条件”的关系呈现，并与物品说明分开。
- 装备需求、武器 DPS/攻击间隔/伤害通道和护甲通道全部直接读取数据库最终面板投影；前端不再读取旧 TIDBI enrichment，也不再用底层百分比自行估算。固定加伤、单精度中间值和逐阶段取整均由数据库统一处理；DPS 存在定义范围时完整保留上下限。
- 装备与套装效果使用数据库的 `display_values_json` 作为结构化数值，详情文本与配装汇总共享相同的游戏取整结果；`raw_values_json` 不进入角色属性累计。
- 武器详情沿用游戏面板的数值在前格式：英文显示“Damage per Second / Attack Speed”，中文显示“每秒伤害 / 攻击间隔”。机制页将固定伤害的简短解释放入可聚焦的信息提示，避免拉长专注属性卡片。
- 配装器的可用孔位直接采用具体物品记录的 `sockets`，不默认假设所有 0 孔装备都已由打孔师加工，也不模拟随机掉落孔数。更换或卸下装备时会清空该栏位的宝石；宝石目录视为无限规划素材，同一种宝石可以重复使用。
- 镶嵌物的武器/护甲效果由其有效 affix 的 `affix_unit_types` 决定：武器读取 `WEAPON`，护甲、盾牌和饰品读取 `ARMOR/TRINKET`。只有当前镶嵌位置触发的结构化效果会进入只读宝石面板、装备效果汇总与属性计算；同一装备内的宝石属性不会反向用于满足该装备自身的属性需求。
- 套装速览列出该套装的全部件数门槛，而非只列当前已激活层级；内容使用原生 `details/summary`，默认收起并保留键盘与辅助技术支持。

## 界面与语言

- 首页入口卡片将数量与箭头收进同一行，属性缩写使用固定宽度和垂直居中的胶囊样式。
- 下拉框的触发器与选项菜单均使用站点自有组件，统一轮廓、焦点、选中态、阴影与键盘操作，装备筛选、语言、配装和赌博页面保持一致。
- 非游戏文本的繁体中文按台湾用语逐项修订；游戏名称、说明和装备效果继续直接采用数据库官方繁中文本。

## 赌博计算器

- 延续参考实现的 11 类物品系数：武器/胸甲 100，腿甲/靴子/肩甲 80，盾牌 75，头盔 73，手套 65，项链/戒指/腰带 60。
- 四个底层价格分别为 `(物品等级 + 4/5/6/7) × 类型系数 × (1 + 孔数 ÷ 10)`。
- 每个底层结果同时展示 `floor` 和 `ceil`，因此界面固定给出八个整数位置；整数结果或两种舍入一致时允许重复。
- 可能价格卡片使用统一的纵向布局间距管理标题、表格和说明，不再依靠标题容器最小高度与单独段落外边距凑出间隔。

## 数据与部署边界

- `tl2-wiki-data/` 整体保留为本地刷新源并继续 ignore；浏览器和 GitHub Pages 只使用已提交的 `public/data`、`public/game-icons` 与静态图片。
- `npm run data:refresh` 需要本地 SQLite 和原始图片；`npm run build`、GitHub Actions 和已发布站点均不需要任何外部数据库。
- 不把约 157 MB 的 SQLite 放入 Git 历史；这样 Git 跟踪内容保持约 23 MB，Pages 工作流可直接发布 `dist/`。
