# 当前实现边界

## 数据职责

- `db/` 是本地 `tl2-db` 仓库链接, 负责 MEDIA 原始数据、投影计算和 `wiki_*` 稳定视图.
- 本项目的导入器只读取 `metadata` 和 `wiki_*` 视图, 将行式关系组装为浏览器使用的 JSON.
- `public/data/` 和 `public/game-icons/` 全部由 `npm run data:refresh` 生成并提交. 构建和部署不依赖本地数据库.
- 站点只发布实际消费的字段. 数据库诊断、来源路径、渲染状态和中间 JSON 不进入公开数据.

## 前端派生规则

- 数据库的 `accessory` 和 `pet_accessory` 在页面中分别映射为 `trinket` 和 `pet`.
- 技能树名称、职业说明和页面配色属于界面元数据. 技能通过数据库的 `class_id`、`tree_index` 和 `position` 接入这些界面信息.
- 技能书的 `school` 是 45 个系列的前端展示分类, 保存在 `scripts/spell-book-schools.json`; 系列、等级和可获取性来自数据库.
- 角色属性、配装、孔位、赌博价格和技能曲线插值由前端计算. 曲线点及末端外推语义来自数据库.
- NG 装备、最终面板值、装备需求、效果文本和镶嵌目标均直接使用数据库投影, 前端不重新计算.

## 发布内容

- 装备数据包含 4,029 条玩家可用的稀有、独特和传奇记录, 包括有可见数值变化的 NG 派生记录.
- 职业技能使用 120 个技能、1,800 个等级和数据库筛选后的可见效果. 有官方等级说明时直接展示该说明.
- 技能书只发布正常游戏中可获取的 175 本. 数据库中的 19 本不可获取记录不发送到浏览器.
- 相位兽按 20 个房间统计. 15 个房间展示官方说明, 其余 5 个只报告游戏数据没有说明, 不补写内容.

## 验证

`npm run data:refresh` 依次执行数据库验证、数据导入和公开数据验证. 常规代码检查使用:

```bash
npm run check
node scripts/smoke-browser.mjs
```
